## M2 evidence and boundaries

- Added property publication/contact/policy editing, stale revisions and immutable enquiry policy/date snapshots. First-unit setup explicitly opens requests after the owner's responsibility acknowledgement. Further units start closed and require deliberate opening; preview access is capped at five, including inactive units. Capacity reductions below upcoming bookings fail. Season/stay-rule changes preserve existing bookings and expose their dates in unit settings. Turnover changes recompute future buffers and reject overlaps.
- Owner manual reservations/blocks, edits/removal and cancellation share the property-row mutation lock with submission/confirmation and maintenance. The migrated GiST exclusion applies only to active allocations. Cancellation and block removal deactivate occupancy atomically; history remains. Manual create commands carry stable IDs/payload hashes for retries. Date edits preserve the original unit; moving bookings between units is deferred.
- Added a fourteen-night scrollable semantic calendar and readable booking/block cards, date navigation and paged requests. Status text identifies bookings, blocks, closed nights and turnover. Private authenticated booking CSV is formula-neutralized and excludes capabilities. The 10,000-row export cap returns an explicit error instead of a partial file.
- The minute worker uses a transaction-scoped PostgreSQL advisory lease, a durable fair property cursor, at most twenty properties and at most one hundred rows per cleanup category/property per tick. Commands still enforce deadlines independently. Private retry receipts clear after 24 hours. Closed unaccepted enquiries redact after 90 days, bookings and linked accepted enquiries after 12 months past departure/cancellation (whichever is later), with upcoming records preserved; nonpersonal history ages out after 24 months. Private past block reasons and activity age out after 12 months. These are provisional product defaults requiring market/legal review before live intake, not a compliance claim. Account closure and backup deletion/recovery coordination are not implemented.
- An upgrade test seeds the M1 schema and proves the migration preserves live allocations and copies guest snapshots. The marked preview cluster was backed up privately under `.local/migration-backups/pre-m2-20261010.dump` before applying M2 locally. The backup file exists; a restore rehearsal is an M5 task and has not been claimed. No sibling database, auth source or production database changed.
